## 已证实的移植缺口

现有脚本从修改过的 P5、P4、Native 和早期六槽底座逐代追加。多个入口读取绝对本机路径和历史修改固件，尚无仅接收用户原厂 BIN 即可重建全部功能的完整入口。

成功 RTOS 在未使用的历史模块中仍含重复颜色数据。已确认两份旧 HNCS 540 系数、三份 HNCS 原生曲线及其他排除胶片。按活动胶片清单过滤无法清除这些副本。

旧 descriptor table 的 `0x540bfa9c` 仍指向 `0x540c1460` 的 HNCS descriptor。P4 → P3 → P2 → P1 的回退链仍存在，需要以实际消费者验证清理后的路由。直接将数据清零可能留下可达的无效对象。

历史模块另有从原厂克隆的 basis/aux 结构及资源。可移植工具应从本次用户原厂输入重建这些内容，并明确自研代码与第三方材料的来源。完整旧 append 区的冻结副本不满足目前的分发准入要求。

## 当前交付边界

能力状态由 `assets/capabilities.json` 记录。数据导入、原生编码、资源验证均可独立执行。菜单主体是可阅读和修改的源码，其胶片注册、分类及分组三个生成头文件明确阻止缺少平台绑定时编译。

当前开发包没有可升级固件输出，也没有已完成的干净框架。构建可用性不得从资源验证、编码验证、用户原有成功版本或容器识别的 PASS 推导。


## Studio Lite 到 Agent

Studio Lite 已能使用公开 51 款库或匹配的本地导入库，保存选片、六槽、名称、分类、图标和备注。Agent 的 `studio-lite/check_project.py` 读取项目，核对库指纹、胶片资产和用户提供的原厂 2.10，返回与项目 SHA-256 绑定的校验结果。

该检查还没有将 Studio 的覆盖字段应用到固件容器。后续构建需要从同一份原厂输入建立独立的生成入口，绑定项目、胶片库与最终 BIN，验证真实菜单、槽位分配、颜色和恢复默认的生产入口。机内自由文本需另外验证字体、宽度和换行。构建及实机结果分别记录，当前不提供可升级文件。
